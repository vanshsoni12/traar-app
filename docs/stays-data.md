# Stays search data

Repository inspection: provider creation, provider dashboard, and admin review use `listings.category`, `address`, numeric `price`, `price_unit`, and optional `latitude`/`longitude`. The category form stores `STAY` for all accommodation; it does not distinguish hotels from hostels. No SQL schema/migrations or rating source are checked into this repository. The deployed database schema has not been independently verified.

The Stays page reads approved STAY listings and their images. It uses `select("*, listing_images(storage_path, sort_order)")` so absent optional columns do not cause a missing-column error. It consumes the following optional fields only if returned:

- `stay_type`: an explicitly recorded Hotel, Hostel, Dormitory, Guesthouse, Homestay, or Resort (case insensitive). Provider/admin data entry and persisted values are needed to classify current STAY records. Unknown types remain visible under All types; names are never used to infer type.
- `rating`: a genuine numeric aggregate on a documented 0–5 scale. A verified review/rating source and aggregation process are needed to populate it; no ratings are generated by this page.
- `latitude`, `longitude`: existing optional coordinate fields. Both must be finite and within geographic bounds. Populate missing values with verified property coordinates to enable nearest sorting.

No database migration was applied. Existing Bhopal sample listings retain their recorded Hotel categories and numeric estimated nightly prices; they have no coordinates or ratings. Samples appear only in Bhopal. Price sorting uses numeric listing prices and retains displayed units; it does not convert different price units to nightly rates. Missing prices are sorted last, separately from the existing trip-budget fallback of zero.

Search matches name and the full stored address (including area); autocomplete uses those same values. Recommended preserves source order. All other sorts are stable, with unknown values last. Nearest uses straight-line Haversine distance, not road distance, and requests location only when chosen. Denied location access leaves the available results usable.

Directions use the Google Maps Directions URL, prefer valid coordinates, fall back to name plus the stored full address, and omit origin so Maps chooses the starting location: https://developers.google.com/maps/documentation/urls/get-started#directions-action
